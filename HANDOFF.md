# Состояние проекта и что дальше

Онлайн-форма ТЗ на разработку продукции вместо Excel-файла заказчика.
Живёт на **https://tz.fmill.ru/**

## Результат

| Готово | Где |
|---|---|
| Форма: 4 блока из Excel, 38 полей, 37 подсказок из колонки «Инструкция» | `src/part-c.js`, схемы `CLIENT` / `SPEC` / `PHOTOS` / `STORAGE` |
| Выбор формы, пористости и надрезов по фотографиям из исходного Excel | `src/img/`, соответствие в `IMG_KEYS` в `src/build.js` |
| Контроль обязательных полей: красное → зелёное, счётчик в шапке | `refresh()`, `badFields()` |
| Несколько изделий в одной заявке | `addItem()`, кнопка «Добавить ещё изделие» |
| Загрузка фото с превью, сжатие до 1500 px в браузере | `addFiles()`, `shrink()` |
| Автосохранение черновика, восстановление после перезагрузки | `save()` / `loadKey()`, ключи `fmill_tz_v1` и `fmill_tz_mgr_v1` |
| Режим коммерческого отдела: загрузка заявки клиента, дозаполнение, утверждение | `openFile()`, `setMode()`, `applyLock()` |
| Выгрузка заявки одним html-файлом со встроенным JSON | `buildDoc()` |
| Печать в PDF из браузера | `@media print` в `src/part-a.html` |
| Хостинг, домен, HTTPS, защита домена от угона | GitHub Pages, `CNAME`, `protected_domain_state: verified` |
| Два готовых приёмника заявок со сборкой PDF | `apps-script.gs`, `yandex-function/` |

## Как устроено

**`index.html` генерируется — править его напрямую нельзя**, следующая сборка сотрёт правки.
Исходники в `src/`, сборка:

```bash
node src/build.js
```

- `src/part-a.html` — стили и токены темы, метка `__FONT__` под шрифт
- `src/part-b.html` — каркас страницы
- `src/part-c.js` — вся логика и схемы полей, метка `__IMAGES__` под фотографии
- `src/img/`, `src/font/` — фотографии вариантов и TildaSans

Сборка воспроизводима: `node src/build.js` из текущего коммита даёт `index.html`
байт-в-байт. После правок — закоммитить и запушить, GitHub Pages подхватит
за пару минут (кэш до 10 минут, проверять с Ctrl+Shift+R).

Вторая цель сборки — версия для Artifact без `<head>`:

```bash
node src/build.js "../tz-razrabotka-produkta.html"
```

## Что осталось

**1. Развернуть приёмник заявок.** Сейчас `SUBMIT_URL` пустой: клиент получает файл
заявки и готовое письмо на info@fmill.ru, отправляет вручную. Два варианта готовы
и описаны в README:

- `apps-script.gs` — Google, ~10 минут, PDF штатными средствами, 100 писем в сутки;
- `yandex-function/` — Яндекс, ~30 минут, данные в РФ, 2000 писем в месяц.

Оба **не проверены вживую** — нужен аккаунт заказчика. Логика сборки PDF в варианте
Яндекса проверена локально: 2 страницы, кириллица и фотографии корректны.
После развёртывания вписать адрес в `SUBMIT_URL` в `src/part-c.js` и пересобрать.

**2. Открытые вопросы к заказчику.**

- Где коммерческий отдел ведёт заявки — вопрос отложен. Если это Битрикс24 или
  amoCRM, приёмник разумнее заменить вебхуком в CRM, а не слать письма.
- Хранилище заявок. Пока его нет: связка идёт файлом через почту. Настоящие ссылки
  вида `tz.fmill.ru/?id=…` для менеджера потребуют базы.
- 152-ФЗ. Форма собирает ФИО, телефон и почту контактных лиц. Требование о размещении
  ПД граждан РФ в России стоит уточнить с юристом — от этого зависит выбор площадки.

**3. Мелочи, если понадобится.**

- Страница закрыта от поисковиков (`noindex`) — снять одной строкой в `build.js`.
- Имя автора в коммитах — `Nick <me.nick.2007@gmail.com>`, менять теперь только
  через force-push.
- OG-картинки для превью ссылки в мессенджерах нет, только текст.

## Ограничения, которые уже учтены

- **Лимит запроса 3,5 МБ** у функций Яндекса. Форма пересобирает payload со всё более
  сжатыми фотографиями (1100 → 800 → 600 → 450 px), пока не уложится в 3 МБ;
  оригиналы не портятся. `PAYLOAD_LIMIT`, `buildPayload()`.
- **`Content-Type: text/plain`** при отправке — иначе браузер шлёт preflight-запрос,
  на который приёмники не отвечают.
- **Архив функции Яндекса 4,9 МБ** — больше лимита консоли (3,5 МБ), деплой только
  через Object Storage.
- **Адрес приёмника виден** в исходниках публичной страницы, поэтому в обоих
  приёмниках есть ограничение частоты. Секреты в `SUBMIT_URL` класть нельзя.
