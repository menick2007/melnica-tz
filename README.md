# ТЗ на разработку продукции — Фабрика «Мельница»

Онлайн-форма технического задания, которую заполняет клиент. Заменяет Excel-файл
«ТЗ на разработку продуктов»: те же четыре блока, но с подсказками, контролем
обязательных полей, выбором формы и пористости по фотографиям и загрузкой референсов.

**Адрес формы:** https://tz.fmill.ru/

Старый адрес `menick2007.github.io/melnica-tz/` отвечает редиректом 301 на новый —
уже разосланные ссылки продолжают работать.

## Что внутри

Один файл — `index.html`, 527 КБ. В нём уже лежит всё: шрифт TildaSans,
фотографии вариантов, стили и логика. Внешних запросов страница не делает,
работает и без интернета, если открыть файл локально.

| Файл | Назначение |
|---|---|
| `index.html` | Сама форма — это и есть сайт. **Генерируется**, править через `src/` |
| `src/` | Исходники формы и сборщик: `node src/build.js` |
| `HANDOFF.md` | Состояние проекта и что осталось сделать |
| `CNAME` | Домен `tz.fmill.ru`. Удалить = вернуться на адрес github.io |
| `apps-script.gs` | Приёмник на Google Apps Script. Не участвует в работе сайта |
| `yandex-function/` | Приёмник на Yandex Cloud Functions + Postbox. Не участвует в работе сайта |
| `.nojekyll` | Отключает обработку Jekyll на GitHub Pages |

## Домен

`tz.fmill.ru` — CNAME-запись в зоне `fmill.ru` (DNS на reg.ru), указывает на
`menick2007.github.io.`. Сертификат выпускает GitHub, продлевается сам.
Основной сайт на Tilda эта запись не затрагивает: у него отдельная A-запись.

## Блоки формы

1. **Клиент** — установочные данные, заполняются один раз на заявку. Служебная секция
   коммерческого отдела клиенту не показывается и отправку не блокирует — она
   появляется только в режиме коммерческого отдела (см. ниже).
2. **Характеристика** — наименование, оборудование, режим выпечки, габариты
   и органолептика (цвет корки, пористость, надрезы, добавки, посыпка).
3. **Фото и референс** — три зоны загрузки и поле для ссылки на облачную папку.
4. **Хранение и упаковка** — сроки годности, условия, упаковка, количество в коробе.

Блоки 2–4 повторяются по кнопке «Добавить ещё изделие» — одна заявка на весь ассортимент.

## Режим коммерческого отдела

Заявка проходит две стадии.

**1. Клиент** заполняет свою часть и нажимает «Отправить». Форма собирает файл
`ТЗ_<клиент>_<дата>.html` — внутри все ответы и фотографии.

**2. Коммерческий отдел** получает этот файл, открывает форму и загружает его:
кнопкой «Загрузить заявку клиента» под заголовком либо просто перетащив файл
на страницу. Дальше:

- сверху появляется полоса «Коммерческий отдел» с наименованием клиента;
- вся клиентская часть переходит в режим только для чтения — поля пунктирные и приглушённые,
  невыбранные варианты бледнеют, зоны загрузки фото скрыты;
- служебный блок раскрывается и подсвечивается зелёным — он единственный активный;
- если в данных клиента нужно что-то поправить, включается флажок
  «Разрешить правку данных клиента» — правка становится осознанным действием,
  а не случайным;
- кнопка меняется на «Утвердить и отправить». Она требует заполнить ФИО менеджера,
  статус согласования и дату, иначе подсвечивает недостающее.

После утверждения файл называется `..._утверждено.html`, а в шапке документа
появляется штамп вида «Согласовал · Смирнова А. В. · 24.08.2026».

Черновик клиента и открытая менеджером заявка лежат в разных ключах `localStorage`
и не затирают друг друга. Режим переживает перезагрузку страницы; выйти из него —
кнопка «Выйти из режима».

## Куда приходят заявки

**Пока `SUBMIT_URL` пустой** — форма собирает файл заявки и открывает у клиента
готовое письмо на `info@fmill.ru` с заполненной темой и сводкой. Клиенту остаётся
приложить сохранённый файл и нажать «Отправить». Фотографии так не вкладываются:
адресная строка их не вмещает, поэтому они идут внутри файла.

**Когда `SUBMIT_URL` заполнен** — форма отправляет заявку `POST`-запросом, а сервис
сам рассылает письма с PDF во вложении. Настройка ниже.

## Автоматическая отправка на почту

Готовый приёмник лежит в этом же репозитории — [`apps-script.gs`](apps-script.gs).
Он принимает заявку, **собирает PDF** и отправляет два письма: коммерческому отделу
и подтверждение клиенту. Стоит ноль рублей.

**1.** Откройте [script.google.com](https://script.google.com) → «Новый проект».
Если нужен ещё и журнал заявок — вместо этого создайте Google Таблицу и в ней
«Расширения» → «Apps Script»: тогда каждая заявка будет падать строкой на лист «Заявки».

**2.** Удалите содержимое `Код.gs` и вставьте туда весь текст `apps-script.gs`.

**3.** В начале файла поправьте адреса:

```js
var MAIL_COMMERCIAL  = 'info@fmill.ru';   // куда падают заявки от клиентов
var MAIL_CORP        = 'info@fmill.ru';   // куда падают утверждённые ФС
var MAIL_TECH        = '';                // технологи, можно оставить пустым
```

**4.** «Начать развёртывание» → «Новое развёртывание» → тип **«Веб-приложение»**.
Выполнять от имени: **я**. Доступ: **все**. Это обязательно — форма обращается
к скрипту без авторизации, иначе запрос не пройдёт.

**5.** Google попросит разрешения и покажет предупреждение о непроверенном
приложении: «Дополнительные настройки» → «Перейти к проекту». Приложение ваше
собственное, поэтому предупреждение ожидаемо.

**6.** Скопируйте выданный адрес вида
`https://script.google.com/macros/s/AKfy…/exec` и вставьте его в `index.html`:

```js
const SUBMIT_URL = "https://script.google.com/macros/s/AKfy…/exec";
```

**7.** Закоммитьте и запушьте — через пару минут форма начнёт отправлять заявки.
Проверить приёмник можно, просто открыв его адрес в браузере: должен ответить
`{"ok":true,"note":"Приёмник заявок формы ТЗ работает…"}`.

### Что нужно знать про этот вариант

- **Лимит Gmail — 100 адресатов в сутки** на обычном аккаунте (1500 на Google
  Workspace). Каждая заявка расходует два письма, то есть примерно 50 заявок в день.
- **Адрес приёмника виден в исходниках** публичной страницы. Поэтому в скрипте стоит
  ограничение `MAX_PER_HOUR = 20` — чтобы посторонний не выжег суточную квоту.
  Секретные токены в `SUBMIT_URL` класть нельзя.
- **Данные идут через Google.** Форма собирает ФИО, телефон и почту контактных лиц —
  это персональные данные. Требование о размещении баз с ПД граждан РФ на серверах
  в России стоит обсудить с юристом; если оно критично, приёмник переносится на
  Yandex Cloud Functions — логика та же, меняется только площадка.
- **Если PDF не собрался**, письмо всё равно уходит — с html-файлом заявки
  и пометкой в теле письма. Заявка не теряется ни при каком сбое.

## Вариант на Яндексе: Cloud Functions + Postbox

Тот же сценарий, но данные и письма остаются в России. Код лежит в
[`yandex-function/`](yandex-function/). PDF собирается через `pdfkit` со вшитым
шрифтом PT Sans — кириллица, фотографии, знак «−18 °C» и кавычки-ёлочки
переносятся корректно, проверено на собранном документе.

**Лимиты.** Функции: 1 000 000 вызовов и 10 ГБ×час в месяц бесплатно.
Postbox: первые 2000 писем в месяц бесплатно. Для ваших объёмов — 0 ₽.

**1. Postbox.** В консоли Yandex Cloud → Cloud Postbox → «Создать адрес»,
указать домен `fmill.ru`, подпись DKIM — «Простая». Сервис выдаст **две
CNAME-записи**, их нужно добавить в зону на reg.ru — так же, как мы добавляли
`tz` и запись верификации GitHub. Проверка занимает до суток, можно ускорить
кнопкой «Запустить проверку».

**2. Ключ для отправки.** Создать сервисный аккаунт с ролью `postbox.sender`,
затем API-ключ со скоупом `yc.postbox.send`. Сохранить ID ключа и секрет —
это логин и пароль для SMTP.

**3. Собрать архив.** В папке `yandex-function/`:

```bash
npm install --omit=dev && zip -r function.zip index.js package.json font node_modules
```

Архив получается около **4,9 МБ**. Это больше лимита загрузки через консоль
(3,5 МБ), поэтому его нужно положить в бакет Object Storage и указать функции
оттуда — там лимит 128 МБ.

**4. Функция.** Cloud Functions → создать функцию → среда `nodejs18` или новее,
точка входа `index.handler`, таймаут 30 секунд, память 512 МБ. Загрузить версию
из Object Storage. **Сделать функцию публичной** — форма обращается к ней без
авторизации.

**5. Переменные окружения** функции:

| Переменная | Значение |
|---|---|
| `SMTP_USER` | ID API-ключа Postbox |
| `SMTP_PASS` | секрет API-ключа |
| `MAIL_FROM` | адрес отправителя на подтверждённом домене, например `tz@fmill.ru` |
| `MAIL_COMMERCIAL` | куда падают заявки от клиентов |
| `MAIL_CORP` | куда падают утверждённые ФС |
| `MAIL_TECH` | технологи, можно не задавать |

Пароль от SMTP лучше держать в Lockbox и подключать секретом, а не вписывать
переменной открытым текстом.

**6.** Скопировать адрес функции и вставить в `index.html` в `SUBMIT_URL`,
закоммитить и запушить. Проверить можно, открыв адрес функции в браузере —
ответит `{"ok":true,"note":"Приёмник заявок формы ТЗ работает…"}`.

### Про размер запроса

У функций Яндекса потолок **3,5 МБ на JSON запроса**. Форма это учитывает:
перед отправкой она собирает payload и, если он не помещается, последовательно
уменьшает фотографии (1100 → 800 → 600 → 450 px), пока не уложится в 3 МБ.
Оригиналы в форме при этом не портятся. Шесть снимков 2400×1800 дают запрос
около 2,2 МБ. Если даже после сжатия не влезает — форма честно скажет об этом
и предложит сохранить файл или убрать часть фотографий.

Шрифт PT Sans — ParaType, свободная лицензия, распространение разрешено.

## Как обновить форму

Через веб-интерфейс GitHub: откройте `index.html` → карандаш → внесите правку →
Commit changes. Через минуту-две GitHub Pages подхватит новую версию.

Из командной строки:

```bash
git add index.html && git commit -m "Правка формы" && git push
```

## Заметки

- Страница закрыта от поисковиков (`<meta name="robots" content="noindex,nofollow">`).
  Если форму нужно индексировать — удалите эту строку из `<head>`.
- Черновик клиента сохраняется в `localStorage` его браузера и восстанавливается
  при возврате на страницу. На сервер ничего не уходит.
- Фотографии сжимаются в браузере до 1500 px по длинной стороне перед вложением.
